What changed, and why

A point-in-time record of the architecture pass of 27 September 2026. Eighteen pieces of architecture were reviewed. All eighteen were changed, across twenty-one merged pull requests. The app is installed and running. Here is each change in plain words, with the reason it was worth doing.

Every number here was measured, not remembered. The "before" figures come from checking out 77a44ae, the commit the work started from, and running the suite there.

Two files were added in their place, and both are things the program needed: a single window-name type, and the shared test harness.

The one idea behind all of it

Most of these findings are the same mistake wearing different clothes. Somebody wrote a piece of code, then wrote a second piece that only forwarded to the first. The second piece adds a name, a file, or a hop — and nothing else. It looks like an organisation. It is a cost.

You pay for it twice. Once when you write it, and again forever when you read it: to answer "what happens when dictation stops", you open four files instead of one and follow a chain of pass-throughs. And because a forwarding layer has no behaviour of its own, it has nothing worth testing, so it silently rots.

The fix is the same every time: delete the layer, and move the knowledge to where the work already happens. Not to a new place. To the place that was already doing the job.

The eighteen, in the order they were done

Ranked by how much they mattered, best first. Each one says what was wrong, what changed, and what it buys you.

1

Five copies of the same test trick

tests/*.test.mjs → tests/harness.mjs · PR #3

To run one of the app's three screens in a test, each test file had its own recipe: read the HTML, pull out the first script block with a pattern, rewrite the last line so the page would not start itself, and invent a fake set of buttons.

The trap: if someone later adds a second script block, the recipe silently keeps only the first half. Every test still passes. The page is half-tested and nobody knows.

3

Asking a question changed the answer

engine_catalogue.rs · asr.rs · voice_activation.rs · PR #16

whisper_runtime() sounds like a getter. It is not. Inside, it reached into the one shared copy of the speech model and rewrote its decoding speed, based on whoever asked last.

So the very act of asking "can this engine run?" changed how the running engine decoded. The wake-word listener asked with a fast setting, won the race, and never put it back. Dictation still worked — but only by accident, because it happened to rebuild its model stack before every dictation.

"Is your model downloaded?" had three answers

local_model.rs · readiness.rs · engine_catalogue.rs · PR #17

This one was a real user-facing bug, not just untidy code.

If you pointed Slugtale at your own model file, the settings window would say "Local model: missing" — while the engine said that same file was fine and ready. Dictation readiness also used that wrong answer to decide whether to warm the model up, so it skipped the download check it should have done.

Worse: two tests were named for exactly this case. They passed — by asserting the wrong behaviour. One was named "uses the default model when your choice is stale", and asserting that is precisely the bug.

7

A promise the code could break

dictation_runtime.rs · dictation_segments.rs · PR #11

When a dictation is long, Slugtale cuts it into pieces and inserts each as you speak. The promise is that pieces arrive in the order you said them, and that if one fails to insert, the ones after it wait so they do not bury your rescue text.

That promise was spread across twelve files and eight traits, with two traits declaring the same two methods and a small bridge passing calls between them. Then review deleted the one line that actually enforces the promise — and all 426 tests still passed.

Six modules answered a question nobody asked

text_insertion.rs · macos.rs · linux.rs · windows.rs · PR #8

After typing a word into your editor, Slugtale either typed it directly or put it on the clipboard and pasted. That distinction is important enough that the project gives it a name. But all six places that insert text returned a value saying which one happened — and the one caller threw the value away.

So if you ever said "it pasted instead of typing", the app had no way to tell you. It never recorded it anywhere.

A file that only forwarded

app_paths.rs → app_files.rs · PR #20

A 69-line file where eight of ten functions just called the function in the next file. It lived in a different part of the program from the one it forwarded to, and its own documentation described the other file.

The reason it existed: the settings file was re-read from disk on every access, 33 times, all funnelling through one global lock. The original author had added a comment explaining that caching was unsafe, because exactly one writer was bypassing the store. One line of policy, turned into a whole-program restriction.

10

What counts as "voice", in three places

segmentation.rs · audio_capture.rs · wake_word.rs · PR #19

The number that decides "the user stopped talking" lived in the segment-pause code. But the real-time audio callback used it too — reaching across the program for a constant from a module that knows nothing about pausing.

The same "is this silence?" rule was also written twice, with no shared name. A mutation report had already recorded that swapping && for || in one copy survived the test suite.

Now the number sits beside the code that produces the level, the silence rule exists once, and a test reads the number out of both the app and the settings window and fails if they ever differ. A comment stops being a promise and becomes a check.

Left open on purpose: the Dictation Bar holds "voice" on screen for 700 ms after you stop, while the detector moves on immediately. Closing that gap means deciding what the bar should show between words — a product decision, not a refactor. Tracked as slugtale-hdef.12.

11

Window names were typing homework

main.rs → window_label.rs · PR #12

Window names were typed out in eleven places across three files. One of the three already had a constant; the other two did not. A typo in the Dictation Bar's name is a silent no-op: the bar just stops appearing, and nothing fails.

The tray menu also used the word "settings" for its own item, the same string the settings window answers to, with nothing to say they were different things. A test now proves the two namespaces cannot collide.

12

The tray was a list of pairs and a lookup table

app_shell.rs · scripts/ · PR #13

The menu existed as a list of identifier-and-label pairs, plus a separate function that read those identifiers back. Adding an item meant editing both. There were five tests for two items.

Three Rust tests were also reading the developer scripts and searching their source text for the word "codesign". They moved to the test tier that owns those files, and the scripts now export what they do so the tests call them. A test can no longer pass because of a comment.

Caught in CI: one of the new tests built its expected command with a path that is wrong on Windows. The script was right; the test was not. Fixed.

13

Names that nothing outside could read

lib.rs and every module · PR #6

Every module re-exported itself into one flat namespace, so about twenty names with no reader outside their own file were available to anything. Among them: the Parakeet licence and attribution text, and the Apple Speech platform list.

Licence text should only be reachable from the code that has to display it. Those twenty names are now private to the module that owns them. A test module still sees them, so no test changed.

14

Three loggers that only forwarded

diagnostics.rs · dictation_host.rs · PR #15

Three small wrappers, thirty lines each, each holding two fields and recording one line. One was built by the code it wrapped, two by the caller — for the same job, in two different places. 155 lines gone; logging now happens where the work happens.

15

The settings window spoke for the backend

main.rs → transcription_engine.rs · PR #21

main.rs matched on which engine it was dealing with, three times, in three different styles, because the engine interface did not offer the four things the settings window needs. A fourth engine would have meant three edits in the file that knows least about engines.

Each engine now answers for its own files. The one refusal that had no business being where it was — "these files belong to macOS, Slugtale cannot remove them" — moved to Apple's own code, next to the engine that owns those bytes. Verified byte for byte. A test holds the exact sentence so it cannot drift.

The payoff: that settings row used to be impossible to test, because it needed a running app. It is now an ordinary unit test. 17 new tests, 14 mutations tried, 14 caught.

16

The second-opinion knobs were decoration

second_opinion.rs · PR #9

Four thresholds that decide when to ask a second speech engine were published as a struct with four public fields, described as "fixed and inspectable". Nothing could change them. The only field anyone ever set was a timeout.

They are now private, and a new test shows a threshold working at a value other than the default — so "inspectable" became true rather than decorative.

17

The build was broken on Linux

linux.rs → PR #4

Not architecture, but it was blocking every other change. A method returned a borrowed value where the signature asked for an owned one. The Linux job had been failing since a commit three weeks earlier; the Mac and Windows jobs never build that file, so nothing local noticed.

Fixed, and proved by compiling both the old and new form rather than by reading them. Then a second failure surfaced behind it: a test asserted something that is only true on a machine with a screen. The Linux runner has no screen. The test now says what is actually true in each case.

18

Two directions were being checked, then one

frontend-seam.test.mjs · PR #5

The frontend and the backend talk by bare text. A test checked that every name the frontend sends exists on the backend — but only the names written as plain text. Four places send the name as a value instead, and were invisible. A typo there does nothing at a user's desk and nothing in the test suite.

The other direction was not checked at all, so a command no screen could reach — which reads in the source as a feature — went unnoticed. Both directions are checked now, and the one known-unreachable command is on a list that empties itself the moment it becomes reachable.

What this cost, and what it bought

Cost

  • Every change was checked twice, against the repo rules and against what it claimed. Five pull requests went round a second time.
  • Three sub-agents and two temporary worktrees, cleaned up afterwards.
  • One behaviour change worth naming: hand-editing the settings file is noticed at the next save rather than instantly.
  • Your in-progress work was moved off main onto its own branch, wip-configurable-segment-pause, so the pull could not land on top of it.

Bought

  • 641 fewer lines of app code (−6.6%), and 2,098 more lines of test code (+20%). There is now more check than program.
  • Two real user-facing bugs fixed: the custom-model readiness lie, and a getter that quietly rewrote running state.
  • A Linux build that had been broken for three weeks, now green — so three platforms build instead of two.
  • Four bugs the old suite was blind to, each now pinned by a test proved to fail when the bug is put back.
  • 1,296 lines of code nothing could reach, and 36 names exported to the whole program for no reason.
  • One Pause Flush path from twelve modules to four, with the rule it depends on named in one place.
  • 36 fewer names to learn before you can safely change something.

Verification note: every figure above was measured by checking out the commit the work started from and counting there, then checking out the finished tree and counting again. None of it is estimated. The +6885 / −4259 raw diff looks large only because most of the additions are tests.
